# Persona effects on work and communication

[Design index](../README.md) · [Identity](../design/01-personas-and-identity.md)

This is a normative refinement of observation and evaluation, not a report of
passed implementation tests or demonstrated persona benefit.

## Mechanism, behavior and benefit are different claims

Continuing identity, current character, relevant retained experience, accepted
obligations and authorized observations can inform a persona's choices. Their
inclusion establishes an available mechanism. A changed choice establishes a
behavioral difference only when it is actually observed. Better work or
communication requires independently assessed outcomes and an appropriate
comparison. None follows merely from a profile, a trait value, a name, a portrait,
a fluent explanation or a count of messages.

Character must not grant access, assign a profession, force a tool choice, weaken
verification or override an accepted obligation. Sensible collaborators may make
the same choice when the evidence favors it. A test must not reward arbitrary
behavioral divergence or punish justified convergence.

## Communication must preserve exact observation

| State | What it establishes | What it does not establish |
| --- | --- | --- |
| Delivered | An input was routed to a recipient. | Inclusion in a decision. |
| Included | An exact input was supplied to an admitted decision. | Provider processing, understanding or agreement. |
| Acknowledged | A valid recipient decision marked its observed input handled. | A correct answer or completed work. |
| Responded | An attributable response or action exists. | That it satisfies the request. |
| Outcome assessed | A declared criterion was checked against evidence. | General competence or a causal persona advantage. |

A cursor orders notifications; it is not proof that every input below it was
observed. Changes in permission or visibility can introduce an older readable
input without increasing the cursor. Admission must validate the actual bounded
page supplied to the decision, including exact notification identities. A new
arrival beyond an unchanged full page need not invalidate that decision, but it
must remain eligible for later observation under the existing scheduling rules.

A model acknowledgment must be bound to the inputs included in its originating
admitted decision. It must not consume a previously unseen input merely because
that input is currently readable and falls below a historical delivery watermark.
Recheck this condition at the mutation boundary, not only at initial action claim.
Missing evidence requires fresh observation; it must not be backfilled with an
invented receipt. Exact action retries retain their existing outcome.

These rules apply to all notification kinds, including work notices and action
receipts, rather than only conversational messages. Multiple notifications about
one subject remain distinguishable. An inclusion receipt identifies the actual
recipient, participation, decision and notification; another participant's or
another decision's receipt cannot supply the missing observation.

Unreadable inputs remain private and pending. They must not be exposed to justify
a rejection, silently acknowledged, or used to force unrelated paid decisions.
Fresh observation still requires current permission, an authorized stimulus and
available funding. A rebuild must not increase allowances or turn uncertain
provider spending into a free retry. Scheduling and stopping rules remain
separate from evidence that an input was actually included.

## Mechanical acceptance scenarios

Observation checks must exercise an older input becoming visible below the same
cursor, a full page shifting to a lower cursor, input removal, and a notification
identity changing while its position is unchanged. An arrival beyond a full page
must not cause an unnecessary replay. Other-run and unauthorized inputs must not
be treated as new observations for the current decision.

Acknowledgment checks must cover a permission change between admission and
mutation, multiple notices for the same subject, every supported notification
kind, mismatched recipient and decision receipts, repeated actions, rollback and
restart. Failed admission leaves no inclusion evidence; failed acknowledgment
leaves the unseen input unconsumed. Historical omissions remain explicit until a
fresh decision actually receives the input. Passing these scenarios establishes
an observation mechanism, not that the persona understood or used the input.

## Assessing actual effect

Use matched within-model trials with declared tasks, seeds, tool access,
permissions, budgets and stop conditions. Compare intact character with a
character-withheld condition and name-swap controls. Verify the actual provider
input and control contamination through accessible memory and peer channels.
Keep task evidence and obligations available equally; withholding character must
not accidentally remove necessary work information. Separate starting-character
comparisons from learned-memory, relationship and longitudinal-development tests.

Assess work through actual artifacts, executable checks where appropriate,
criterion coverage, documentation consistency, defects, rework and accepted
outcomes. Assess communication through factual and actionable responses, uptake
of supplied corrections, missed requests, unnecessary clarification, duplicate
work and successful handoffs. Acknowledgment rate, enthusiasm, distinctive voice
or agreement alone is not communication quality. Legitimate disagreement and
explicit uncertainty can be successful outcomes.

Use reviewers blinded to persona identity and condition where feasible, with
criteria declared before inspecting the results. Preserve failures and incomplete
runs. Report calls, tokens, latency and spending alongside quality: more activity
or more elaborate prose may cost more without improving the result. Measure the
observation repair separately from character effects so a transport improvement
is not misattributed to personality.

Report the conclusion as improved, no detected difference, mixed, regressed or
inconclusive within the tested scope. State sample size, task coverage, model
revision uncertainty and other limitations. Small pilots can validate delivery
or expose defects without establishing a general advantage. Build checks, runtime
mechanism tests, observed behavior and independently assessed benefit must remain
separate in both reports and operator displays.
