# Persistence and host execution

`state.sqlite` uses WAL and full synchronous writes. One node process owns its directory through an operating-system file lock. Records keep stable IDs, an entity kind and scope, a revision, timestamps and extensible JSON data. Revisions retain previous values. Events assign an ordered sequence to application changes. Documents are immutable versions with parent IDs; two children of the same version both survive. Character updates with a stale expected revision create a preserved conflict instead of replacing the current character.

Every public operation supplies an action ID and immutable request. SQLite records the claim before execution. Repeating the same ID returns the existing result; changing its request is rejected. Internal record changes and their successful action results commit in one transaction. External host effects cannot share a database transaction. Those are represented by tracked jobs with receipts and incremental output. The job supervisor is a separate instance of the same executable image, so replacing the installed binary or restarting the node does not change the supervisor already executing a command.

The node reconciles completed receipts and matching process start identities after restart. An absent receipt and unverified process identity yield an uncertain outcome. No automatic retry of such an action is permitted. Explicit resolution appends an outcome and supporting evidence. A cancelled command retains its prior output and the fact that already performed effects were not rolled back.

Calls preserve the exact application request, provider response, observed model and usage, raw provider events and errors. Unknown usage is represented explicitly. Application history remains available when a persona selects a shorter active context. Compaction changes what is supplied to later decisions, not the archived source history.

Artifacts are files addressed by SHA-256. Publication copies exact bytes into the artifact store. Submissions refer to immutable artifact and document IDs. The work's current submission points to the most recent submitted version; a review of an older version retains its finding without changing the current version's state. Artifact inspection checks its digest because another program with shared host access could have changed a file outside application operations.

Continuity bundles stream a tar archive containing the persona record and revisions, selected learning and dependencies, communication, action history, related work and call evidence, native files and artifact bytes. Node identity keys and provider login credentials are not part of the bundle. Import validates content and paths, checks blob digests, preserves record conflicts, and starts imported runs paused. Host-specific links are reported rather than treated as portable installations. Other nodes or programs may still possess copies; application pause is not a distributed exclusivity guarantee.
