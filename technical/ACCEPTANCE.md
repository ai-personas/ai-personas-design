# Acceptance: what must actually be demonstrated

[Specification](SPEC.md) · [Implementation order](RELEASE.md) · [House example](../examples/HOUSE.md) · [Status](../STATUS.md)

A design, a schema, a tool installation, a picture and a successful live task are different kinds of evidence. Preserve both failed and passed attempts. The following IDs retain the final v1.2 specification's mechanical and behavioral campaign.

## Mechanical gates

Use zero-model-call tests through actual Rust public-API and supervisor paths wherever possible. A scripted provider can test transport mechanics, not emergent judgment. An abstract model of a guard cannot stand in for an implementation regression.

| ID | Required test and passing observation |
|---|---|
| M01 | Same ID/body returns the same receipt; altered body conflicts; unauthorized receipt lookup fails |
| M02 | Concurrent adoption preserves one current head plus visible alternatives/conflicts; no silent overwrite |
| M03 | Expired/lost actor or writer fences reject late mutations; genuine late evidence still records usage |
| M04 | Inbox/outbox crash/restart preserves delivery/deduplication without new grants |
| M05 | Concurrent births respect root capacity/rate/depth/resources; retry creates one identity and funded initialization |
| M06 | Birth, membership and commitment acceptance remain separate; no inherited secret or broader grant |
| M07 | Descendant calls/retry/compaction/review are charged; unknown usage is not silently refunded |
| M08 | Per-work context/overflow preserves mandatory scope, authority and constraints; forbidden/superseded memory is not silently active |
| M09 | Changed criterion/input/manifest/policy invalidates applicability; queued invalidation never leaves a false current pass |
| M10 | Missing analysis inputs, failed required execution, unsupported image input or fabricated outputs cannot satisfy evidence |
| M11 | Cross-work/private graph/search/UI leaks fail, including revoked resources and derived summaries |
| M12 | Malicious packages/artifacts/prompt injection cannot access keys, assessor authority or ungranted effects; no unrestricted fallback |
| M13 | An ambiguous outside effect stays unknown; no blind duplicate publication or charge |
| M14 | UI projects authoritative state, replays correct scoped events and disposes viewers/focus correctly |
| M15 | HTTP provider capability/schema/media/refusal/partial response/cancel/retry/model-ceiling conformance |
| M16 | Legacy import preserves bytes and unknown bindings; backup/rollback reconciles effects |
| M17 | Pending tool suppresses the unobserved same-decision suffix, including restart; no early inspect/publish/submit |
| M18 | Newborn decides using only exact permitted preview/seed before membership; parent data stays inaccessible |
| M19 | No accepted continuation means visible awaiting/unowned work; missing outcomes do not inherit another owner's completion |
| M20 | Conditional evidence never qualifies unconditional claims; assumption authorization is not fact confirmation |
| M21 | Blocking finding survives delivery/acknowledgement/compaction; critical update is not starved behind ordinary messages |
| M22 | Cyclic final prerequisites are diagnosed; permitted version-ready iteration can run; unresolved final checks still block full acceptance |
| M23 | Exploration/birth cannot spend closeout allocation; authorized transfers conserve root and unknown exposure remains reserved |
| M24 | Coupled assembly adoption/release is atomic; both update-versus-seal orderings preserve history/currentness |
| M25 | Metadata-only activity cannot extend root/self-wake ceilings; useful negative work remains representable |
| M26 | Both result-versus-await-registration orderings retain runnable/notified work; keep the existing newer-input wait regression |

Start M17 with an existing output file and a delayed successful writer; repeat with delayed failure and unknown termination. Inject crashes around intent commit, launch, result capture, notification, adoption and sealing. File absence alone can conceal an early-publication defect.

## Behavioral gates

These require actual persona decisions and real outputs at appropriate scope. The house walkthrough is a designed test, not evidence that B11 passed.

| ID | Test | Required observation |
|---|---|---|
| B01 | Same need, different individuals | Meaningful attention/method/artifact differences, assessed separately from requirement adequacy |
| B02 | Same persona, different partners | Interaction affects choices without merely erasing continuing identity |
| B03 | Same members, different shared history | Relevant relationship/agreement history affects coordination |
| B04 | Character/relationship ablation and names-only substitution | Differences are not explained only by wording, labels or uncontrolled sampling |
| B05 | Feedback-to-edit-to-review | One persona's evidence changes another's exact artifact and independent checking verifies it |
| B06 | Unexpected useful improvement | An unprompted opportunity is tested and improves the agreed result or yields informative rejection |
| B07 | Evidence-driven reprioritization | A disturbance changes accepted work instead of blind continuation |
| B08 | Useful birth and no-birth restraint | Expansion produces a distinct inspectable contribution when useful; simple work can finish without growth |
| B09 | Retained correction and counterevidence | Later behavior improves against matched memory-withheld runs; erroneous advice is revised |
| B10 | Model-switch continuity | Identity/learning and boundaries persist across allowed models without provider-private authority leakage |
| B11 | Full house plus disturbance | Native coordinated architecture/structure/plumbing/HVAC/electrical, actual analyses, revalidation, exact review and honest outside limits |
| B12 | Unrelated needs | Software/data/writing/research/conversation/ongoing fixtures use the same primitives without kernel task branches |

## Controlled comparisons, not a personality performance

Keep original request and frozen clarifications equal, with the same tool opportunity and total resources. Compare one continuing persona, a fixed team and an adaptive team. Separately vary character, partner, shared history, retained learning, model and tool effects. An improved result caused by more compute is not evidence of emergent coordination.

Repeat matched cohorts and counterbalance order/presentation effects. Record actual model IDs, settings, capabilities, all attempts, usage and unused allowances. Blind quality review where appropriate. Do not require a birth, fragment write or trait change on every task; that rewards unnecessary activity.

Predeclare task-specific quality, cost, robustness thresholds and repeat counts. The sources do not establish one universal pass percentage. Different valid results are permitted; identical choices may be correct under decisive evidence. Evaluate difference and adequacy independently.

## Adversarial house cases

Remove one required system; inject a clash; change a layout after analysis; omit native sources; provide unexecuted simulation prose; present an irrelevant completed command as a review; spend ordinary resources near exhaustion; decline the newborn invitation; acknowledge a blocking finding without repair; race adoption against release.

The expected behavior is a supported correction or accurately bounded result, not a forced successful design. Do not choose a mandatory tool, profession roster or order to make the benchmark easier. Applicable external site, jurisdiction, professional and physical requirements remain separate from digital acceptance.

## Evidence to retain

Keep exact runtime/design/UI/schema/fixture/evaluator revisions, original user information, models/settings, contexts and inclusion manifests, decisions/actions/receipts, resources including unknowns, actual files and hashes, review scopes and findings, failed alternatives, source-to-analysis mappings and final dispositions. Protect private data and secrets; preserved evidence is subject to access/retention policy.

A corrected evaluator is a new version with the original failure retained. Never rewrite learner evidence or weaken the rubric invisibly to manufacture a pass. Documentation checks and UI fixture checks do not unlock an engineering gate by themselves.
