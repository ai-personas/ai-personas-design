# S4 — Reliability safeguards: make freedom dependable

**Role:** rationale for the consolidated behavioral safeguards. This code-free brief replaces the current reading copy of the historical v1.2 implementation specification. The original remains in Git history; its old stack and branch instructions are not requirements for understanding this handbook.

## What the revision resolved

Persistent identity and voluntary organization are not sufficient by themselves. Individually sensible choices can still leave a need unowned, produce incompatible results, exhaust review capacity, or attach an old pass to a new artifact.

The solution is not a hidden project manager that chooses every task. It is a set of observable contracts that preserve freedom while making obligations, effects, uncertainty, and completion dependable.

| Problem | Adopted safeguard | Why it does not impose a domain workflow |
|---|---|---|
| Everyone contributes but nobody carries the need forward. | Actual continuation acceptance and visible required-outcome ownership gaps. | Participants still choose whether and how to accept; the system exposes absence rather than inventing an owner. |
| An exploration premise becomes a real-world fact. | Versioned assumptions and claim-specific conditionality. | Conditional work remains possible without pretending external confirmation. |
| A newborn needs membership to understand an invitation. | Restricted, funded pre-membership orientation; separate creation, membership, and commitment. | The participant can inspect permitted terms, negotiate, or decline. |
| A launched tool is treated as completed. | Pending effects suppress the unobserved remainder of the decision; actual results inform a fresh decision. | Independent subsequent work may continue within its own bounds. |
| A friendly acknowledgment makes a blocker disappear. | Findings persist until an evidence-backed or legitimately authorized disposition. | The responsible participant chooses repair, justified dispute, allowed deferral, or escalation. |
| Each discipline waits for another's final version. | Explicit provisional inputs and bounded negotiated iteration. | Participants choose the experiment and compatibility checks; final acceptance still needs current evidence. |
| Exploration consumes all finishing capacity. | Protected review, agreed repair, and closeout allocation inside the same root allowance. | No universal percentage or forced method is imposed. |
| Narrative activity extends work indefinitely. | Finite root, retry, population, and wake bounds that metadata cannot reset. | Useful negative results and legitimate waiting remain representable. |
| An update arrives between review and release. | One coherent release binds exact current inputs, criteria, assembly, findings, review, and authority. | It checks consistency of the agreed state, not whether the domain judgment is true. |

## Four guarantees that should never be conflated

Reliable state is not correct engineering. Correct execution is not appropriate method selection. A completed review is not automatically independent or qualified. Human acceptance of a conditional result is not outside professional or physical assurance.

The system must present those distinctions where the claim is made. It cannot bury material assumptions only in an appendix or show a green current pass while invalidation waits in a queue.

## Preserve the earlier principles

Individual agendas coexist with an unranked shared board and actual commitments. Documents remain ordinary documents; fragments are authored learning. Domain checking is available in real work through tools and suitable review. Tool availability, representative use, task competence, and evidence applicability remain separate.

Authority only narrows downstream. Descendants, retries, context work, and reviews share the controlling allowance. Unknown external effects require reconciliation before repetition. Imported content cannot grant permissions, expose secrets, or bypass evaluation boundaries.
